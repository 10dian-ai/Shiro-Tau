# 工作图与回退

工作图是每个会话的一份记录：发生了什么、谁决定的、文件怎么变的。回退、审计都建立在它上面；后续阶段的多 agent 调度和验证闭环也会往同一张图里写。

## 存在哪里

```
~/.shiro/agent/workgraph/<会话 ID>/
  log.jsonl     事件日志，只追加，一行一个事件
  blobs/        文件内容快照，按内容的 SHA-256 存放，相同内容只存一份
```

不保存的会话（`--no-session`）用临时目录，会话结束时删除：运行期间照样可以回退，结束后不留痕迹。

日志的第一行是文件头（格式版本、会话 ID、工作目录）。每次追加都同步写盘，崩溃最多丢失正在写的那一个事件；启动时发现最后一行写了一半会自动截掉。日志损坏到读不了时，shiro 把它改名留在原地、另起一份新的，并在启动时告诉你，不会因此无法工作。

## 记录哪些事件

| 事件 | 内容 |
| --- | --- |
| `session.start` | 会话开始或恢复的原因 |
| `user.message` | 你提交的提示 |
| `checkpoint` | 检查点：名称，以及当时对话所在的位置 |
| `tool.call` | 工具名和输入（过长的字符串会截断，完整内容在快照里） |
| `policy.decision` | 放行还是拒绝；由谁决定（规则、模式、hook、用户，或"没人可问"）；在流水线的哪一步；依据的规则；当时的模式 |
| `hook.run` | 哪个 hook、退出码、耗时、结果（包括因未审查而跳过） |
| `file.change` | 哪次工具调用改了哪个文件，改前改后的内容哈希（不存在记为 null） |
| `irreversible` | 一次效果无法撤销的操作，比如会改东西的 shell 命令或 MCP 工具调用 |
| `tool.result` | 是否出错，结果的前 400 个字符 |
| `rewind` | 一次回退：恢复了哪些文件、删除了哪些、哪些因冲突没动 |

每个事件有序号、时间、发起者（目前都是 `main`）和一个指向前一个事件的 `parent`。回退不删除历史：回退事件的 `parent` 指回检查点，从那里长出一条新的分支，旧分支仍然留在日志里。

`/audit` 显示最近的权限判定和当前分支上改过的文件；日志本身是普通的 JSONL，可以直接用 `jq` 查。

## 检查点

每次提交提示时自动打一个检查点，名称是提示的第一行。也可以手动打：

```
/checkpoint 重构之前
```

检查点本身不复制任何文件。文件内容是在**工具调用改它之前**才存快照的，所以没被 agent 碰过的文件不占空间。

## 回退

```
/rewind          从列表里选一个检查点
/rewind 12       直接指定编号
```

选定检查点后会先显示计划，再让你选：

- **Restore files and conversation**：文件和对话都回到检查点。
- **Restore files only**：只恢复文件，对话保持现状。
- **Restore conversation only**：只把对话退回去，文件不动。

计划里列出：

- 自检查点以来被 agent 改过的每个文件。检查点时还不存在的文件会被**删除**，并明确标出。
- 无法撤销的操作：自检查点以来运行过的、会改东西的命令。它们的效果不在回退范围内，这里只是提醒你自己处理。

### 对话怎么回退

对话退回到检查点之后那条提示**发出之前**，那条提示的文字回到输入框里，可以修改后重发。底层用的是 Pi 的会话树：原来的对话分支没有被删除，用 `/tree` 还能回去。

### 冲突

回退只应该撤销 agent 的改动。如果一个文件在 agent 改过之后又被别的东西改了（你自己在编辑器里改的、某条命令改的），它现在的内容就和日志预期的不一样。这种文件会单独列出来问你：

- **Restore the rest, keep these files as they are**：保留这些文件，恢复其他的。
- **Restore everything, overwrite these files**：一起覆盖。
- **Cancel**

已经和检查点时内容相同的文件不算冲突，也不会被重写。

## 范围和限制

- **只跟踪文件工具（`edit`、`write`）的改动。** shell 命令、MCP 工具创建或修改的文件不在快照里，回退不会恢复它们，只会在计划里列出相应的命令。
- 回退的是文件内容。数据库、远程服务、已经推送的提交、已经安装的依赖这些副作用无法撤销。
- 用 Pi 自带的 `/tree`、`/fork` 移动对话不会动文件；想让文件和对话一起回去请用 `/rewind`。
- `/fork`、`/new` 开的新会话有自己的工作图，不继承原会话的检查点。
- 旧会话的工作图目前不会自动清理。需要腾空间时可以删除 `~/.shiro/agent/workgraph/` 下对应会话的目录。
