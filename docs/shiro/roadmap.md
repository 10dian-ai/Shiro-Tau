# 路线图

Shiro-Tau 的目标是把 Claude Code、Codex 和 DeepSeek Harness 各自的长处做进一个以 Pi 为主体的工具里，而不是把它们拼在一起。整个计划分五个阶段。这份文档说明每个阶段做什么、现在做到哪里。

## 阶段 1：地基（进行中，当前版本 0.1.0）

后面所有功能都要经过的东西：一套信任系统、一张工作图、一个常驻的宿主进程和一个桌面端骨架。这一版完成了前两样和 hooks，后两样还没有开始。

| 内容 | 状态 |
| --- | --- |
| 以 Pi 1.5.2 为主干建立仓库，命令改为 `shiro`，配置目录改为 `~/.shiro` | 完成 |
| 工作图：事件日志、内容快照、文件历史、检查点、回退、审计 | 完成 |
| 策略引擎：五种权限模式、允许/询问/拒绝规则、命令规则、受保护路径、工作区边界 | 完成 |
| 读取 Claude Code（`settings.json`）和 Codex（`.rules`）的权限配置 | 完成 |
| 审批对话框，会话内"不再询问" | 完成 |
| Hooks 兼容层：六个事件的 command hook，读 Claude Code 和 Codex 的配置，项目 hook 审查 | 完成 |
| `/permissions`、`/hooks`、`/checkpoint`、`/rewind`、`/audit`，`shiro policy` 命令 | 完成 |
| 操作系统级沙箱（文件和网络隔离） | 未开始 |
| `auto` 模式（由守护模型判断风险） | 未开始 |
| 其余 hook 事件（`PreCompact`、`SubagentStop` 等）和类型（`prompt`、`agent`、`http`） | 未开始 |
| shiro-host 与协议：agent 作为常驻服务运行，界面通过协议连接 | 未开始 |
| 桌面端骨架：会话列表、对话、diff 审查、终端、文件编辑 | 未开始 |

阶段 1 的关卡是两个验收场景：

- **安全防线**：仓库里被改过的 hook 不执行；越权的写操作被拦截并写进审计。这一版里 hook 审查、拦截和审计已经可用；网页注入那一半要等浏览器（阶段 3）。
- **全局时光机**：回退时代码、浏览器页面、服务器上的文件同时还原。这一版只做到本地文件和对话一起回退。

## 阶段 2：多 agent

- 子代理（兼容 Claude Code 和 Codex 的定义）、agent teams、动态工作流。
- 每个 agent 独立的 git worktree 和本地环境；文件租约，两个 agent 不会同时改同一个文件。
- Agents 总览、Plan 与 Goal、跨会话消息。
- 按角色路由模型（规划用一个模型，执行用另一个）；自建网关和账号池，限流时自动切换账号。
- 多 agent 的事件写进同一张工作图，可以按 agent 回退和审计。

## 阶段 3：验证闭环

- 内置浏览器、元素评论、browser use、开发者模式、预览与自动验证。
- 电脑操作（先 macOS 后 Windows）、Appshots。
- 代码审查、PR 监控、安全扫描。
- 证据（测试输出、截图）附在对应的改动上，评审时一起看。

## 阶段 4：远程与自动化

- SSH 主机、会话迁移、把 VPS 当云用、断线续跑、手机端。
- 定时任务、Monitor、channels、webhook。
- 无头模式与 SDK、CI 集成。

## 阶段 5：DIY 与生态

- 服务槽位、profile 与补丁、四种预设。
- 插件管理与市场、设置卡片、界面扩展、插件评测。
- 兼容 Claude Code、Codex、Pi 和 DeepSeek Harness 现有的插件与技能。
- Record & Replay、桌宠与主题、IDE 和浏览器扩展、协作空间、分享页、语音。

## 原则

- **Pi 是主体。** 新能力长在主干里，不是外挂的扩展包。
- **一套信任系统。** shell、文件、浏览器、桌面操作、远程、MCP 都走同一条判定流水线，写进同一份审计记录。
- **一张工作图。** 每个 agent 的每个动作都记在同一张图上，回退、审计、验证证据都从这里来。
- **实现而不是照搬。** Claude Code 的功能只根据公开文档独立实现，不使用它的代码。
